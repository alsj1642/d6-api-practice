API

비유: 주문 창구

날씨 앱은 날씨를 직접 재지 않아요. 기상 데이터를 받아 와요. 배달 앱이 메뉴를 직접 만들지 않는 것과 같아요. 그 "받아 오는 창구"가 API예요. 주소를 바꾸면 주문이 바뀌어요.

API 키

비유: 회원 카드

창구에 따라 회원 카드가 필요한 곳(코스트코)도 있고 필요 없는 곳(동네 분식집)도 있어요. 오늘 쓰는 창구는 전부 회원 카드 없이 주문돼요. 실무에서 만나는 API는 대부분 키가 필요해요 → D8에서 키 숨기는 법을 배워요.

JSON

비유: 이름표 붙은 상자

{ }는 상자, "이름": 값은 이름표 붙은 칸, [ ]는 번호 붙은 줄(0번부터), 점(.)은 상자를 여는 길. data.rates.KRW = 큰 상자 → rates 상자 → KRW 칸.

실패 화면

비유: 가게 문에 붙은 "잠시 쉽니다"

무료 API는 가끔 느리거나 멈추고, 예고 없이 바뀌기도 해요. 안내문이 없으면 사용자는 하얀 화면만 보고 떠나요. 그래서 로딩 중·불러오기 실패 화면은 필수예요.

규칙 만드는 규칙

비유: 좋은 체크리스트 = 좋은 업무 지시

① 검사할 수 있게(예/아니오) ② 하지 말 것도 + 대신 할 것 ③ 이유 한 줄 ④ 짧게, 제자리에(루트·폴더·local·스킬) ⑤ 실수가 나오면 규칙을 고친다. 규칙 한 줄 = 검사 한 줄이에요.

규칙 먼저, 만들기는 AI가, 검사는 내가

비유: 주방 위생 수칙 + 검식

오늘은 완성 파일이 없어요. 폴더 CLAUDE.md에 API 화면 규칙을 붙여 두고 프롬프트로 만든 뒤, 검사 4가지(🔌 표시 · API 상자 · 실패 화면 · 출처·기준 날짜)로 확인해요. CLAUDE.md는 부탁이라 가끔 안 지켜요 — 그걸 찾는 게 오늘의 AI 실수 찾기예요.

    ## API 화면 규칙
- 키가 필요 없는 공개 API만 쓴다. 주소에 `key=`, `token=`, `apikey=`가 필요하거나 문서에 Authentication이 있으면 만들지 말고 "이 API는 키가 필요해서 D8 방식이 필요해요"라고 알려 줘. (왜: HTML은 누구나 코드를 볼 수 있어서 키가 새어 나감)
- API 주소는 파일 맨 위 `const API = { ... }` 한 곳에 모으고, 각 줄에 `// 🔌` 주석을 단다. `fetch` 하는 줄에도 `// 🔌 API 호출` 주석을 단다. (왜: 어디가 API인지 바로 찾으려고)
- 화면 맨 아래에 "🔌 이 화면이 쓰는 API" 상자를 두고, 실제로 부른 주소와 "새 탭에서 원본 JSON 보기" 링크를 보여 준다. (왜: 주소를 바꾸면 주문이 바뀌는 걸 눈으로 보려고)
- 카드마다 **로딩 중** 문구와 **불러오기 실패** 화면을 넣는다. 한 카드가 실패해도 다른 카드는 보이게 따로 부른다. (왜: 무료 API는 멈추거나 바뀜)
- 화면에 **데이터 출처**를 적는다. Open-Meteo는 "Weather data by Open-Meteo.com". (왜: API 규칙이 출처 표기를 요청함)
- 날짜가 있는 데이터(환율 등)는 **기준 날짜**를 함께 보여 준다. API 문서가 실시간이라고 하지 않으면 "실시간"이라고 쓰지 않는다. (왜: 환율은 하루 한 번 발표되는 기준값)
- HTML 파일 하나에 CSS와 JavaScript를 함께 넣는다. 더블클릭으로 열려야 한다. (왜: 설치 없이 바로 확인하려고)
- 커밋·푸시는 하지 말고, 커밋 메시지만 제안한다. (왜: 세이브 포인트는 내가 검사한 뒤에 찍음)
