# /api-check — API 화면 규칙 검사기

너는 **검사만 하는 사람**이야. 이 화면을 만든 대화는 모르는 상태로, 파일과 규칙만 보고 판단해. 파일은 **절대 고치지 않아.**

## 무엇을, 무엇으로 검사하나
- 검사 대상: `$ARGUMENTS`에 적힌 HTML 파일. 비어 있으면 `d6-api/`의 `.html` 파일 전부.
- 기준: `.claude/rules/api.md`의 `## API 화면 규칙`과 `## 실수에서 배운 규칙`의 모든 줄.
  - `api.md`가 없으면 `d6-api/CLAUDE.md`를 기준으로 써. 둘 다 없으면 검사하지 말고 "규칙 파일이 없어요"라고만 알려 줘.

## 순서
1. **위험 먼저:** 주소에 `key=`, `apikey=`, `token=`, `YOUR_API_KEY`가 보이면 보고 맨 위에 **위험**으로 적어.
2. 규칙 파일을 읽고 규칙을 한 줄씩 목록으로 만들어.
3. HTML 파일을 읽고, 규칙마다 지켰는지 **코드에서 근거(줄 번호)** 를 찾아.
4. 결과는 넷 중 하나로 적어.
   - **지킴**: 코드에서 근거를 찾음
   - **안 지킴**: 규칙과 다른 코드를 찾음
   - **모름**: 코드만 봐서는 알 수 없음 (근거를 못 찾았으면 "지킴"이라고 쓰지 마)
   - **해당 없음**: 이 화면이 쓰지 않는 API의 규칙 (예: 공휴일 API를 안 쓰는 화면의 Nager.Date 규칙)

## 보고 형식
규칙 한 줄 = 표 한 줄. 같은 내용을 두 번 적지 마.

| 규칙 | 결과 | 근거 (줄) | 사람이 직접 확인할 것 |
| --- | --- | --- | --- |
| 🔌 주소를 `const API` 한 곳에 | 지킴 | 10–18, 157 | Ctrl+F로 `🔌`를 찾아 주소가 맨 위에 모여 있는지 보기 |

- **사람이 직접 확인할 것:** 규칙 줄에 `→ 검사:`가 있으면 그 내용을 그대로 써. 없으면 화면에서 확인하는 방법을 한 줄로 써. 예: 주소 글자 하나를 지우고 새로고침해서 그 카드만 실패 안내가 뜨는지 보기.
- **고칠 곳:** 표 아래에 **안 지킴** 항목만 모아 한 줄씩 적고, 고치는 방법은 제안만 해. 없으면 "고칠 곳 없음"이라고 적어.
